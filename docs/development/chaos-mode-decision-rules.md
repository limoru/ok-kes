# 自动卡厄思模式判断逻辑对照手册

本文档汇总卡厄思模式（`ok_tasks/ChaosMode.py` + `ok_tasks/utils_chaos.py` +
`ok_tasks/utils.py` 中被卡厄思模式使用的通用函数）里所有带条件判断的处理
逻辑，按"页面/场景 -> 判断条件 -> 执行动作"的形式列出，方便测试时对照实际
游戏表现是否符合预期。

> 本文档只做行为记录，不代表需求文档；如果代码后续变更，本文档需要同步
> 更新才能保持对照有效。

---

## 0. 页面处理总入口与优先级顺序

`ChaosMode.run()` 每帧执行一次 OCR，然后按 `utils_chaos.PAGE_HANDLERS` 列表
顺序依次尝试每个页面处理函数，**排在前面的函数优先命中**，一旦某个函数返回
`True` 就停止本帧后续处理。顺序如下（节选自代码内注释，完整列表见
`utils_chaos.py` 文件末尾）：

1. `handle_auto_stop` —— 达到"几轮后停止"配置轮数则自动停止任务
2. `handle_save_target_member` —— 主界面进入信息统计页面获取目标主战员特征
3. `handle_route_selection` —— 路线选择页面
4. `log_credit` / `log_node_status` —— 仅记录信用点/胜率，不拦截
5. `handle_stuck_log` —— 画面卡住检测兜底
6. `handle_close_page` —— "点击屏幕"提示，优先于其他普通页面
7. `handle_refine_equipment_credit` —— 提炼装备信用点页面，优先于确认按钮
8. `handle_center_confirm` —— 页面中央确认按钮
9. `handle_archive_target_member` —— 信息统计页面记录目标主战员
10. `handle_chaos_mask_engraving` —— 面具卡牌刻印获取页面
11. `handle_equipment` —— 装备选择/安装
12. `handle_card_assign`
13. `handle_confirm` —— 通用确认按钮
14. `handle_mask_card` —— 面具卡牌获得页面
15. `handle_convert` —— 通用转换按钮
16. `handle_shop` —— 德朗商店

21. `handle_copy` —— 复制按钮

25. `handle_expedition_result` —— 探险结果页面（优先于下一步）

30. `handle_settlement` / `handle_destiny_choice` / `handle_main_member_flash` / `handle_card_reward` / `handle_select_card` / `handle_copy_member` / `handle_convert_card` / `handle_discovery_select` / `handle_negotiation`

## 1. 主界面 / 存档主战员识别

### 1.1 `handle_save_target_member`（主界面）
- 条件：当前血量百分比可识别（`_get_current_hp_percent` 非 `False`） **且**
  已配置"刷存档主战员"（非空） **且** `node_status["save_target_member"]`
  仍为 `False`。
- 动作：点击进入信息统计页面。

### 1.2 `handle_archive_target_member`（信息统计页面）
- 前置：识别到 `memberinfo`/`memberinfo2` 特征，点击进入并进入统计详情。
- 若"刷存档主战员"配置为空：直接关闭页面，`return True`，不做任何匹配。
- 否则读取当前出战三名主战员名字，逐个跟配置做**双向子串匹配**
  （`target_name in member_name or member_name in target_name`）：
  - **命中**：保存 5 张运行时特征图（`target_member_small`、
    `target_member_in_select_card`、`target_member_tiny`、
    `target_member_in_mask_card`、`target_member_large`），
    `node_status["save_target_member"] = True`，关闭页面。
  - **三人均未命中**：调用 `_clear_target_member_features` 清空内存缓存
    与磁盘特征图片，`node_status["save_target_member"] = False`，
    **调用 `task.disable()` 停止整个卡厄思模式任务**，关闭页面。

> 测试要点：故意把配置名字改成没在场的主战员，确认任务会自动停止，并且
> 下次重新启用任务时会重新走一遍识别流程（不会因为残留缓存而误判）。

## 2. 存储数据价值层级判断

统一读取配置"存储数据价值大于等于多少层级"（默认 `12`），用于以下三处：

### 2.1 `handle_season_chaos_initial_page`（赛季卡厄思初始页面）
- 识别不到"再次观测"按钮或识别不到层级数字：`return False`（交给其他处理）。
- 层级 >= 配置值：`return False`（不点击，交给后续"进入"处理）。
- 层级 < 配置值：点击"再次观测"，`return True`。

### 2.2 `handle_zero_system_initial_page`（零式系统初始页面）
- 逻辑同上，命中"进入"文本区域即认为是该页面；层级不足则点击重新合成坐标。

### 2.3 `handle_discovery_select`（发现选择页面，获得法典）
- 三个选项区域逐个识别层级，**选第一个满足 >= 配置值的选项**并点击。
- 全部选项都不满足：点击取消坐标。

## 3. 事件任务选择（`handle_event_task`，卡厄思/出击共用）

按以下顺序判断，命中即停止：

1. **奖励图标优先**：区域内识别到 `taskreward` 特征且位置在指定范围内，
   直接点击。
2. **禁止选项过滤**：每个选项左上角固定偏移区域内识别到 `forbidden_event`
   特征，则该选项被剔除，不参与后续任何匹配。若全部选项都被禁止，
   `return False`（跳过本次选择）。
3. **check 特征优先**：区域内识别到 `check`/`check2` 特征（取置信度更高的
   一个），直接点击。
4. **Y 坐标 < 0.925 的任务立即选择**：命中即点击，不再往下判断。
5. **刷初始卡牌 / 刷空档**（仅在 `pass_final_boss_count==0 且
   node_count==0` 的初始节点生效，二者不能同时开启，"刷初始卡牌"优先）：
   - 刷初始卡牌：选择包含"传说卡牌"关键词的选项；未找到则点击 ESC 重新开始。
   - 刷空档：选择包含"移除2张"关键词的选项；未找到则点击 ESC 重新开始。
6. **treasure 特征优先**：指定区域内识别到 `treasure` 特征，直接点击。
7. **第一级：必选任务优先级**（新增）：在全部未被禁止的选项中匹配
   "必选任务优先级"配置，命中即直接选中，**完全忽略后续的拉黑过滤**。
8. **第二级：拉黑任务过滤**（仅在第一级未命中时执行）：过滤掉描述命中
   "拉黑任务"关键词（子序列匹配）的选项；若过滤后一个选项都不剩，则**兜底
   还原成过滤前的原始列表**（避免卡死在无选项可选的页面）。
9. **第三级：任务优先级 + 装备优先级**：在拉黑过滤后的选项中，按
   "装备1/2/3号位优先级 + 任务优先级"顺序做子序列匹配，命中第一个即选中。
10. **attack_event 兜底**（仅卡厄思模式）：以上均未命中，且识别到高置信度
    （阈值0.95）的 `attack_event` 特征，点击进入战斗任务。
11. **随机兜底**：以上全部未命中，从当前可选列表里随机选一个。

> 测试要点：构造一个选项同时命中"必选任务优先级"和"拉黑任务"关键词，
> 确认它会被选中而不是被过滤掉；再构造一个只命中"任务优先级"和"拉黑任务"
> （不命中必选）的选项，确认它会被拉黑过滤掉（除非它是唯一选项）。

## 4. 路线选择（`handle_route_selection`）

- 判定页面：识别到 `position` 特征，或识别到"无法接收到梦境号"提示文本。
- 进入页面时：`node_status['flash_or_rest'] = True`；若"进入商店"配置开启，
  同时 `node_status['shop'] = True`。
- **无普通节点特征 = 到达最终 boss**：
  - `node_status['reach_final_boss'] = True`，`node_type = "boss"`。
  - 若"第几层boss前自动暂停"配置不为"不暂停"，且当前已通过层数正好等于
    "配置层数 - 1"，则**暂停整个执行器**（`og.executor.pause()`），
    `return True`。
  - 否则直接点击进入 boss 节点。
- **有普通节点**：
  1. 识别 `safezone`/`enemy`/`elite`/`event`/`settlement` 五种节点类型。
  2. 识别特殊标记特征 `shop`/`kalei`/`seal`/`hard`，各自归属到**距离最近**
     的普通节点上（一个特殊特征只能归属一个节点）。
  3. 排序优先级：**商店节点固定最高优先级**（不受"路线优先级"配置影响）
     > 节点类型（按"路线优先级"配置顺序，"结算"永远排最后）
     > 特殊特征优先级（`shop`/`kalei`/`seal` 为 -1，`hard` 为 +1，负数
     更优先）> 位置从上到下、从左到右。
  4. **小地图规划优先**：先用左下角小地图连通关系规划整条路线
     （`recognize_map_connections` + `find_best_map_route_by_priority`），
     再用右侧当前可点击节点做校验：
     - 规划结果与当前识别的节点类型+特殊特征完全一致 -> 按规划结果进入。
     - 不一致，或规划失败，或规划要求的节点序号超出当前实际识别数量 ->
       **改用步骤3的排序结果兜底**。
  5. 点击命中节点（点击位置相对节点中心做了固定偏移 `-0.095, -0.0065`）。
- 离开路线选择页面（当前不是路线页但 `enter_new_node` 为 True）：
  `node_status['node_count'] += 1`。

> 测试要点：故意让小地图规划和当前节点识别结果不一致（比如遮挡小地图），
> 确认会正确降级到"当前节点优先级排序"兜底，而不是选错节点或卡死。

## 5. 装备选择/安装（`handle_equipment`）

### 5.1 页面/模式识别
- 判定页面：标题文本为"装备"。
- 子页面区分：右上角提示文本包含"请选择主战员" -> **安装装备界面**；否则
  为购买/选择候选装备界面（本手册主要覆盖安装装备界面的分配决策）。
- 购买页面判定：底部同时存在"取消"和"购买"按钮。

### 5.2 购买页面价格与信用点检查（早于分配决策）
1. 识别价格失败：按"价格低于当前信用点"继续购买流程（不因识别失败而放弃）。
2. 价格 > 当前信用点：点击"取消"，`return True`。
3. **（刻印模式专用）** 若"刷装备刻印"开启且"刷装备刻印信用点下限" > 0
   且当前信用点 < 该下限：点击"取消"，`return True`（不评估购买）。

### 5.3 目标主战员定位
- 用 `leveltag` 特征识别最多 3 名主战员位置（按置信度去重、按 y 坐标从上到下
  排序）。
- 用已保存的 `target_member_tiny` 特征图匹配目标主战员位置（阈值 0.4）。
- 若"刷存档主战员"配置存在于 `default_config`：`preferred_member_index` =
  匹配到的目标主战员下标（可能为 `None`，表示未匹配到）。
- 若未配置该项（理论上不会发生，因为默认配置里一直存在）：默认选第一位。

### 5.4 装备分配决策 —— 两套判断标准二选一

**A. "刷装备刻印"关闭时（默认，原有逻辑）：**
1. 读取目标主战员当前三个槏位的实时品质（颜色识别），同步刷新
   `equipment["qualities"]`/`equipment["names"]`/`equipment["descriptions"]`
   记录（实际为空的槏位会清除旧记录）。
2. `_should_install_equipment`：
   - 新装备命中配置优先级 且（当前装备未命中优先级 或 新装备优先级序号
     更小） -> 应该安装。
   - 当前装备命中优先级 且（新装备未命中 或 当前优先级序号更小） ->
     不应该安装。
   - 优先级都未命中或都相同：比较品质等级（未安装0 < 普通1 < 史诗2 <
     传说3），新品质更高才安装。
3. **传说装备互斥**：若新装备是传说品质，且目标主战员其他槏位已经装有
   传说装备，则强制改判**不安装**（避免重复浪费传说装备名额）。

**B. "刷装备刻印"开启时（新逻辑，`utils_equipment_engraving.should_assign_to_target_member`）：**

判断标准从"名字优先级+品质"整体切换为"候选装备能否推进目标名+目标刻印的
进展"，不再调用 `_should_install_equipment`，不做传说装备互斥判断。

**"装备刻印优先级"配置本身是有序列表，填写顺序即优先级高低，排在越前面
（下标越小）优先级越高。** 只有命中排名第一（下标0）的刻印才算该槏位真正
"完成"；命中排名靠后的刻印，槏位仍应继续尝试替换成更靠前的刻印。用
`best_engraving_rank(description, keywords)` 取描述命中的刻印中排名最靠前
的下标（越小越优，未命中任何关键词返回 `None`）。

对目标主战员当前槏位状态（`slot_rank`=当前命中的最优排名，`None`表示无
刻印）+ 候选装备信息（`candidate_rank`=候选命中的最优排名），按下表判定：

| 槏位当前状态 | 候选装备情况 | 判定 |
|---|---|---|
| 已完成（装备名命中目标名列表 **且** `slot_rank == 0`，即已拿到排名第一的刻印） | 任何候选 | **不分配**（该槏位不再变动） |
| 未完成 | 候选命中的刻印比槏位当前更优（`candidate_rank < slot_rank`，或槏位当前无刻印而候选有刻印） | **分配**（优先占住更优刻印，不论候选叫什么名字） |
| 未完成 | 候选**完全不带任何目标刻印**，且候选**是**目标名 | **分配**（继承机制：无刻印装备覆盖会继承原有刻印，不会降级，安全换名） |
| 未完成 | 候选**完全不带任何目标刻印**，且候选**不是**目标名 | **不分配** |
| 未完成 | 候选带有与槏位当前**同等优先级**的刻印（`candidate_rank == slot_rank`），且候选**是**目标名 | **分配**（刻印等级不变，名字变对，安全进展） |
| 未完成 | 候选带有与槏位当前**同等优先级**的刻印，但候选**不是**目标名 | **不分配**（没有新进展） |
| 未完成 | 候选带有比槏位当前**更差**的刻印（`candidate_rank > slot_rank`，注意不是"没有刻印"） | **不分配，无论候选是否为目标名**（候选自带的较差刻印会直接覆盖，不会继承槏位当前更好的刻印，安装会导致刻印降级，必须拒绝） |

"目标名列表"沿用"装备X号位优先级"配置（双向包含匹配）；"目标刻印"沿用
"装备刻印优先级"配置的有序列表（描述文本包含关键词即命中该项，取命中项
中排名最靠前的），**不区分1/2/3号槏位**，但"某槏位当前命中到第几名"是按
槏位各自独立追踪的。

> 关键区分点：候选"完全不带任何刻印"（走继承机制，安全）和候选"带有比
> 当前更差的刻印"（会直接覆盖，导致降级，必须拒绝）是两种完全不同的
> 情况，绝不能混为一谈——即使后者恰好命中目标装备名，也不能安装。

### 5.5 分配结果执行
- **应该安装**（`should_install_first=True`）：点击给目标主战员的行。若是
  购买页面，随后点击"购买"。
- **不应该安装**：从"除目标主战员之外"的候选队友里随机选一个安装
  （`other_members` 本身就过滤掉了 `preferred_member_index`，因此目标主战员
  绝对不会在这个分支被选中，无论开关是否开启）。若无其他队友可选：
  - 购买页面：点击"取消"。
  - 免费安装页面：若存在"提炼"按钮则点击提炼，否则 `return False`。

> 测试要点（刻印模式，"装备刻印优先级"配置至少填2-3项按优先级排序的关键词）：
> 1. 目标主战员槏位为空时，先出现一件"随便名字+最高优先级刻印"的装备，
>    确认会分配给目标主战员而不是随机分配。
> 2. 紧接着出现一件"目标名+无刻印"的装备，确认也会分配给目标主战员（验证
>    继承路径），且不会被判定为"没有进展"。
> 3. 该槏位达标后（目标名+排名第一的刻印），再出现任何装备，确认都不会
>    分配给目标主战员。
> 4. 出现"错误名字+更差优先级刻印"的装备，但槏位已经有更高优先级的刻印，
>    确认不会被分配（避免刻印降级）。
> 5. **关键回归场景**：槏位当前已经拿到排名第一（最高优先级）的刻印，但
>    装备名字还不是目标名；此时出现一件"目标名+排名靠后（较差）的刻印"
>    的装备，确认**不会**被分配——如果错误地分配了，会把已经拿到的最优
>    刻印降级成较差的刻印，这是必须避免的降级 bug。
> 6. 槏位当前只拿到排名靠后（非最优）的刻印，出现一件"随便名字+排名更
>    靠前的刻印"的装备，确认会被分配（继续追求更高优先级，不会因为已经
>    有一个刻印就停手）。
> 7. 槏位已经拿到最高优先级刻印+目标名（完全达标）后，再出现同样命中最
>    高优先级刻印的装备，确认不会重复购买/安装（对应用户最初反馈的
>    "重复获得同一优先级刻印是否会再买一次"问题，应确认为不会）。
> 8. 关闭"刷装备刻印"开关后，重新走一局，确认装备分配行为与开启刻印功能
>    之前完全一致（品质/优先级比较、传说互斥逻辑均正常）。

## 6. 商店（德朗商店，`handle_shop`）

判定页面：识别到"移除卡牌"文本，或对应位置识别到"售"字（售罄）。

1. **移除卡牌**：
   - 已售罄：`node_status['shop'] = False`，继续挑选其他商品。
   - 未售罄：读取移除费用。若本局已移除卡牌数 >= 5（固定上限），不再使用
     信用点移除；否则费用 <= 当前信用点 且 `node_status['shop']` 为 True
     时，点击移除并 `return True`；否则记录日志，继续往下挑选其他商品。
2. **挑选卡牌/装备商品**：
   - 用 `credit_icon` 特征定位所有商品的信用点图标，按 x 坐标排序。
   - 用 `attack_in_shop`/`skill_in_shop`/`enhance_in_shop` 特征判断哪些
     信用点图标对应的是"卡牌"类商品（绑定到最近的信用点图标），其余视为
     "装备"类商品。
   - 逐个商品判断：名字识别失败，或价格识别失败，或价格 >= 当前信用点 ->
     跳过。
   - 卡牌类：若本局已获得中立牌数达到固定上限，跳过该卡；否则匹配
     "卡牌奖励优先级"配置（含"刷初始卡牌"置顶逻辑）。
   - 装备类：
     - "刷装备刻印"**关闭**（默认）：依次用"装备1/2/3号位优先级"三份配置
       分别做双向匹配，命中任意一份即可。
     - "刷装备刻印"**开启**：不按名字过滤，但会先跳过"本次货架周期内已
       判定不满足刻印进展"的装备名（`node_status["shop_engraving_rejected_names"]`
       黑名单，按标点符号归一化后的名字比较，避免货架列表页与购买详情页
       两次OCR识别的标点差异导致漏判），避免反复点开同一件已确认不满足
       的装备导致后面的商品永远没机会被检查。剩下的商品只要价格 < 当前
       信用点就视为"满足"，点击进入详情页（因为货架名字看不到刻印，
       无法在这一步判断，必须点进详情页才能读取刻印描述并交给购买页
       逻辑决定）。黑名单会在货架刷新（免费或花费信用点）、以及每局/
       每层重置时清空。
   - **命中任意一项配置**（或刻印模式下价格合适） -> 点击对应信用点图标，
     `return True`（只点第一个符合条件的商品，不会一次性点多个）。点击后
     进入购买详情页，由 `handle_equipment` 继续处理实际购买/取消决策。
3. 全部商品都不满足购买条件：
   - 识别到左下角"免费"刷新按钮：点击刷新，清空刻印黑名单，`return True`。
   - 免费次数用完（该区域改为显示花费信用点的刷新按钮）：仅当"刷装备
     刻印"开启，且当前信用点 > "刷装备刻印信用点下限"配置（与购买时的
     阈值判断共用同一个配置项，默认300）**且**当前信用点 >= 刷新费用时，
     才点击花费信用点刷新（同样会清空刻印黑名单）；否则不刷新，
     `return False`。
   - 刻印关闭且识别不到免费按钮：`return False`。

## 7. 卡牌闪光/复制/移除的统一入口（`handle_select_card`）

- 判定：固定坐标处文本匹配 `请选择(\d*)张*.*?(移除|复制|闪光|灵光).*?卡牌`
  正则，提取数量和动作类型。
- 动作类型映射到配置 key：移除->"移除卡牌列表"，复制->"复制卡牌列表"，
  闪光/灵光->"闪光卡牌列表"。
- 若动作是"移除/复制/闪光/灵光"且当前是卡厄思模式：先调用
  `_scroll_to_target_member_for_card_removal` 滚动定位目标主战员所在行。
- 调用通用 `select_card` 执行实际选卡（内部还有"优先移除基础牌"、
  "刷空档时优先移除目标主战员同排卡牌"、"闪光时排除已命中闪光优先级的
  卡牌"等子规则，逐张点击直到选够数量或翻到底部）。

### 7.1 卡牌闪光效果选择（`handle_view_original`，查看原件/之前的闪光）
- 按"闪光优先级"配置顺序，对每张卡的"名称+描述"做子序列匹配，命中第一个
  即选中该卡。
  - 若命中的是优先级列表第一项，且"首层刷特定闪光"配置开启，记录
    `node_status["get_specific_flash"] = True`。
- 若识别到 `target` 特征卡牌，**优先于闪光优先级匹配结果**，直接点击。
- 若命中"需要冥想的卡牌"配置中的卡：
  - 本次选中的卡是该卡本身，或没有 target 特征 -> 标记为"无需冥想"
    （`meditation_completed = chosen_card is None and not target_boxes`
    的取值口径，实际含义见下方"冥想判定"小节）。
- 都未命中：随机选一张。

### 7.2 复制卡牌选择（`handle_copy_card_choice`）
- 识别到 `target` 特征卡牌：优先点击。
- 否则按"复制卡牌列表"配置顺序匹配卡名（子串匹配），命中第一个即选中。
- 全部未命中：`return False`（交给其他兜底逻辑）。

## 8. 休息 / 冥想（`handle_rest`）

- **可休息条件**：识别到休息特征 且 区域内文本包含"免费" 且
  `node_status['flash_or_rest']` 为 True。
- **可冥想条件**：`flash_or_rest` 为 True 且识别到 `meditate` 特征 且能
  识别冥想费用 且存在"待冥想"的卡牌（冥想状态字典中至少一项为 `True`）且
  当前信用点同时大于"多少信用点以上冥想"配置值 **和** 本次冥想费用。
- **两者都可选**：按当前血量百分比决定 —— 血量 < 50% 优先休息，否则优先
  冥想。
- **只有一项可选**：选那一项。
- **都不可选**：若存在休息特征但区域内没有"免费"文本，记录日志但不点击。

### 8.1 冥想状态如何被标记为"待冥想"
在 `handle_view_original` 里，如果本次触发的闪光卡牌命中了"需要冥想的
卡牌"配置：
- 若最终选中的卡就是它本身，或者没有出现 target 特征卡牌需要抢 ->
  标记为 `meditation_completed`（无需冥想，也就是这次的闪光效果被判定为
  "已经满足"）。
- 反之 -> 标记为待冥想（下次休息区会尝试点冥想重刷）。

冥想状态在 `reset_layer_status`/`reset_mission_status` 时会被
`_reset_meditation_state` 按当前"需要冥想的卡牌"配置重新初始化（每层/每局
重来一次，不会跨层保留"已满足"的旧状态）。

## 9. 面具卡牌相关（卡厄思模式特有）

### 9.1 `handle_chaos_mask_engraving`（面具卡牌刻印获取页面）
- 判定：标题含"面具卡牌刻印"，且确认按钮已激活。
- 读取"面具卡牌刻印"配置（目标刻印描述）。
- **有"替换"文本（A逻辑，双刻印槏位）**：
  1. 点击刻印1，读取描述。未命中配置 -> 检查"新刻印"描述是否命中（命中则
     交给确认按钮处理，`return False`）；否则检查剩余刷新次数，有则刷新，
     否则点击跳过。
  2. 刻印1命中 -> 继续点击刻印2，逻辑同上（命中则点击跳过，因为两个都
     满足；未命中则检查新刻印/刷新/跳过）。
- **无"替换"文本（原逻辑，单槏位）**：直接读取描述，命中配置则交给确认
  按钮（`return False`）；未命中则检查刷新次数，有则刷新，否则 `return False`
  （交由其他逻辑处理，比如确认按钮本身可能已经可以点击跳过之类）。

### 9.2 `handle_mask_card`（面具获得卡牌页面）
- 判定：标题同时包含"面具"、"获得"、"卡牌"。
- "指定面具卡牌"配置为空：直接点击跳过。
- 识别到的"人格面具"卡牌数量 < 3：说明已经选过，点击跳过。
- 首次进入该页面（`target_mask_card_position == -1`）：**长按**每张卡逐一
  查看详情，用 `target_member_in_mask_card` 特征判断这张卡是否属于目标
  主战员，记录命中的位置索引（找到即停止继续长按后续卡牌）。
- 若未识别到属于目标主战员的卡：默认使用从左到右第 1 张。
- 对选定位置的卡：描述文本子序列命中"指定面具卡牌"配置 -> 点击该卡。
- 未命中：检查剩余刷新次数，有则点击刷新，否则点击跳过。

## 10. 卡厄思专属结算与奖励流程

### 10.1 `handle_chaos_reward_claim`（奖励领取页面）
- 判定：识别到"获得"文本。
- 读取"当前/最大战利品验证卡"数字：
  - 当前数 > 0：点击"获得"。
  - 当前数 == 0：把"领取奖励(只使用验证卡)"配置**自动重置为 False**
    （并通知 UI 刷新），点击取消。
- 识别不到验证卡信息：直接点击取消。

### 10.2 `handle_chaos_reward_settlement`（奖励结算页面）
- 判定：标题含"结算"。
- "领取奖励(只使用验证卡)"配置为 False：不处理奖励，交给
  `_finish_only_first_layer` 判断是否需要因为"只打第一层"提前退出。
- 配置为 True 但未识别到"获得"按钮：同上交给 `_finish_only_first_layer`。
- 识别到"获得"按钮：点击领取。

### 10.3 `_finish_only_first_layer`（多处复用的提前退出判断）
- 若已通关层数 >= 1：
  - "首层刷特定闪光"开启 且 本层未获得指定闪光：成功次数+1，点击退出。
  - "只打第一层"配置开启：成功次数+1，点击退出。
- 否则不处理，返回 `False`。

## 11. 存储数据收集完成（`handle_data_collected`）

- 判定：识别到"存储数据收集完成"文本。
- "保留大于多少TB的存档"配置 <= 0：保留全部，不删除，`return False`。
- 否则逐个 `deletecards`/`deletecards2`/`deletecards3` 特征，读取对应存档
  价值数字：
  - 价值 > 保留阈值：跳过删除（继续检查下一个特征）。
  - 价值 <= 阈值，或价值识别失败（按原逻辑点击删除）：点击该删除按钮，
    `return True`（每次只处理一个，下一帧继续处理剩余的）。
- 全部处理完：交由通用按钮逻辑继续处理（`return False`）。

## 13. 探险结果统计（`handle_expedition_result`）

- 判定：识别到"探险结果"标题。
- 识别到"完成"文本：`success_rounds += 1`（除非"只打第一层"配置开启或已
  逃脱，逃脱状态下不计入成功）。
- 未识别到"完成"：视为失败，不增加成功计数。
- `total_rounds` 无论成功失败都会 +1。
- 处理完毕后调用 `reset_mission_status`，保留统计类状态
  （`total_rounds`/`success_rounds`/`save_target_member`），重置其余节点
  状态。

## 14. 状态重置时机一览

| 函数 | 触发时机 | 保留的字段 | 清空/重置的字段 |
|---|---|---|---|
| `reset_all_status` | 切换模式（`enable()`时禁用另一模式并调用） | 无 | 全部节点状态 + 目标主战员装备状态 + 冥想状态 |
| `reset_mission_status` | 一局探险结束 | `total_rounds`、`success_rounds`、`save_target_member` | 其余节点状态、装备状态、冥想状态 |
| `reset_layer_status` | 通关一层 | `pass_final_boss_count`、`total_rounds`、`success_rounds`、`save_target_member`、`target_mask_card_position`、`get_specific_flash`、`removed_card_count`、`neutral_card_count` | 其余节点状态、装备状态、冥想状态 |

> 测试要点：确认"刷存档主战员"的识别结果（`save_target_member`及已保存的
> 特征图）能跨局、跨层保留，只有重新启用整个卡厄思模式任务才会被清空
> 重新识别。
